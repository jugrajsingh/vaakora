# Changelog

This project is built on [Handy](https://github.com/cjpais/Handy) v0.10.1 and documents its own changes on top of it, following [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Changes merged in from upstream are documented in upstream's own release notes.

## [Unreleased]

### Added

- Tables in the read text are read cell by cell, left to right and top to bottom: box-drawing tables (light, heavy, double and rounded lines), ASCII tables with `+---+` rules and Markdown tables. A cell that wraps onto several lines is read as one value. Each value is read with its column name ("Lane: B, the walk."), after "Table, 3 columns, 2 rows." and each "Row 1.", and the table ends with "End of table." Border characters are not spoken. While a row is read the reader highlights the whole row, and resuming inside a table starts again at the beginning of that row. Reads sent with `vaakora read` are read the same way. Box-drawing characters are never spoken anywhere, including in code read aloud (tree output reads as its file names). A table that cannot be read with confidence is read in its original order without its borders.

### Changed

- A fenced code block that holds only a table is read as a table, also when Read code blocks is off; any other code block is still replaced by "code block skipped".

## [0.2.0] - 2026-11-24

### Added

- A local control socket: while Vaakora runs it listens on `$XDG_RUNTIME_DIR/vaakora.sock` (or `$VAAKORA_SOCKET`), readable and writable only by you, and answers only processes running as your user. It speaks JSON-RPC 2.0, one message per line, in the shape of upstream pull request #1906, with protocol version 1. The socket's folder must belong to you and be closed to other users, as `$XDG_RUNTIME_DIR` is, or the socket is not opened; a file, or the socket of a Vaakora that is still running, is never removed from the socket path.
- Read aloud, History marks reads that came from the command line or an agent: the row shows a small "from agent" tag beside the voice tag, never cut short. Reads saved before this version count as your own. The first start of this version adds an `origin` column to `tts-history.db` and changes no stored read; going back to 0.1.0 afterwards leaves read-aloud history unavailable but intact, and starting this version again brings it back.
- The socket can read text aloud (`tts.read`, saved in history as from agent), pause, resume and stop the reader, list downloaded voices, report what the app is doing (`status`), and toggle or cancel a dictation exactly as `--toggle-transcription`, `--toggle-post-process` and `--cancel` do. A read sent during a dictation is refused and the dictation goes on. A one-shot run (`--transcribe-file`, `--list-models`, `--list-devices`) never opens the socket.
- `transcribe.file` transcribes an audio file with the running app the way Transcribe a file in History does: the file is added to History and transcribed in the background, after any dictation, and the call answers with the text when the job ends.
- Command line: `vaakora read [file|-]` reads a file or piped text aloud (never text given as an argument, which other programs could see), `vaakora pause`, `resume` and `stop` control the reader, `vaakora status` and `vaakora voices` report (add `--json` for JSON), `vaakora dictate [--post-process|--cancel]` toggles or cancels a dictation, and `vaakora transcribe <file> [--json]` prints a file's transcript. They talk to the running app and exit 3 when it is not running (they never start it), 4 when a dictation is in progress, 5 when a model is missing, 2 on a usage error and 1 on any other error.
- `vaakora agent install [--claude] [--codex] [--dry-run]` writes two skills, vaakora-read and vaakora-stop, for Claude Code (`~/.claude/skills`, with `disable-model-invocation: true`) and Codex (`~/.agents/skills`, with `allow_implicit_invocation: false`), so an agent reads aloud only when you invoke `/vaakora-read` or `$vaakora-read`. It never overwrites a skill folder it did not write, and `vaakora agent uninstall` removes only its own: the files it wrote and its marker, then the folders only when nothing else is in them, printing `skip` for any it keeps. Installing again over a folder it wrote replaces the files it wrote there and nothing else. A skill that has to read text from the conversation writes it to a file in `$XDG_RUNTIME_DIR` (never in a repository) and deletes the file once `vaakora read` exits 0, so the text is never on a command line.

### Known issues

- Right after the app starts, `vaakora read` can answer exit 5 (`tts-unavailable`) for a moment, while read aloud is still loading. Run it again.
- In Claude Code, the `vaakora-read` skill deletes its temporary text file after reading, and Claude Code may ask once before it allows that deletion.

## [0.1.1] - 2026-11-23

### Fixed

- The Read aloud popup has rounded corners. Its page background no longer paints a square behind the rounded card, so the corners show the desktop. The popup keeps the app theme; its edge uses the stronger line colour so it shows on a dark or a light desktop, the card radius is the 12 px card radius, the text is 14 px on 20 px with 12 px time and state labels, the close button is a 28 px round button like the dictation pill's cancel, a highlighted sentence that wraps keeps rounded ends, and the progress fill is rounded. On Windows the popup no longer draws the native window shadow.
- In the Vocabulary tab, Listen on a symbol plays natural words, `file_name` for `_`, `file.name` for `.`, `file/name` for `/` and `file~name` for `~`, in place of "alpha_beta" read as "alpha underscore beta". A currency sign added as a symbol plays an amount (`₹100`). Hovering or focusing Listen shows the text it plays ("Plays: file_name"). Listen in the entry dialog still plays the words you typed.

## [0.1.0] - 2026-11-23

First Vaakora release. It starts from Handy v0.10.1 plus the changes below; see UPSTREAM.md.

### Added

Read aloud (text to speech)

- A Read aloud shortcut (default Super+Alt+R, changeable under General) reads the text you last copied. It takes the clipboard with `wl-paste` on Wayland and `xclip` on X11. A popup opens and starts reading at once. Pressing the shortcut again while the popup is open reads the new clipboard text from the start in place of the current text, and stops reading and closes the popup only when the clipboard text is the same as the popup's text (ignoring line endings and surrounding whitespace) or the clipboard is empty or not text.
- The popup shows the text with the sentence being read highlighted, and the highlight follows the audio. While a read is playing or paused, clicking or pasting no longer stops it; use Edit text. After a read finishes or fails the text stays in the reading view and becomes editable when you click it. It shows the time read and about the total (for example 1:18 / about 1:29) with a progress bar and a state word, and has Play and Pause buttons but no Stop: Pause keeps your place, Close ends the read, and Play after a finished read reads again. Edit text on a finished or failed read opens the editor without restarting the read. Read clipboard is a text button next to Play that replaces the text with the clipboard text and reads it from the start, even when the text is the same. An empty clipboard, or one that is not text, leaves the popup as it is. Esc and the close button close the popup and Ctrl+Enter plays or pauses.
- A failed read shows one reason line above the controls, "Read aloud failed." and the reason, in the error colour and at most two lines long. When the chosen model is not downloaded, the line has a Choose a model button that opens Models, Read aloud. If the chosen output device cannot be opened, reading falls back to the default output device and a line with a warning icon says so (an error line replaces it). If a dictation is still pasting when you press the shortcut, a notice asks you to try again, and if the voice worker is not ready a notice says reading is unavailable.
- Eight downloadable voice models: Pocket TTS (English, the default; about 296 MB, 27 voices), Supertonic 3 (about 401 MB, 10 voices), Kokoro-82M INT8 (about 107 MB, 28 voices), Paradee-8M INT8 (about 8.5 MB, 4 voices), Phonon 31M English (about 79 MB, 26 voices) and Indic Tiny TTS for Indian English, Hindi and Punjabi (about 91 MB each, 2 voices each). Each file is pinned to a Hugging Face revision with a fixed size and SHA-256, and downloads are verified and resumable.
- Paradee-8M v1.2, a small and fast English voice model distilled from Kokoro, with four voices (two American, two British). It runs on the CPU only, about 55 times faster than real time at normal speed on the machine the ratings were measured on, and its card credits its author and Kokoro (Apache-2.0). Text with nothing to pronounce reads as a tenth of a second of silence.
- Phonon 31m English, a small English voice model by Gradium built on Pocket TTS and the Mimi codec, with 26 voices (a default voice plus 25 American and British voices). It runs on the CPU only, about 16 times faster than real time at normal speed on the machine the ratings were measured on, and its card credits Gradium (Apache-2.0), Pocket TTS and the Mimi codec by Kyutai (CC-BY-4.0), and the voice set (Apache-2.0). Text with nothing to pronounce, such as only punctuation, dashes or emoji, reads as a tenth of a second of silence.
- Indic Tiny TTS, small voice models by Sulabh Katiyar for Indian English, Hindi and Punjabi (Gurmukhi script), each with a female and a male voice. They run on the CPU, about 20 (Punjabi) to 48 (English) times faster than real time at normal speed on the machine the ratings were measured on, and on an Intel GPU through OpenVINO; there is no NPU path. Hindi and Punjabi spell English words and abbreviations letter by letter in their own script, and name path symbols in it (for example slash, dot and underscore), so technical text such as `README.md` is read and not dropped. Text with nothing to pronounce reads as a tenth of a second of silence. Each card credits the model (CC-BY-4.0), the voice data (LIMMITS 2024 for English, the AI4Bharat Rasa dataset for Hindi and Punjabi, CC-BY-4.0) and the Vocos vocoder by Charactr Inc. (MIT), and the English card notes that the source does not document speaker consent for release.
- Pocket voices are gated on Hugging Face. Accept the voice terms there, then enter a Hugging Face token in the gated model's details in Models, Read aloud; it is the only place to enter one. After the gated model is downloaded, the field stays in its details while a token is set, so you can clear or change it. The token you enter there is kept in memory for this run only and is cleared when the app restarts. Its draft is discarded when the details close, after Save and when you leave the page. How the token is stored and the backend's `HF_TOKEN` fallback are unchanged.
- Each model runs on the CPU through ONNX Runtime, or on an Intel GPU or NPU through OpenVINO (Paradee-8M and Phonon run on the CPU only, Indic Tiny has no NPU path, and Pocket TTS keeps part of its work on the CPU: on the GPU only its text conditioner runs there, and on the NPU only its main flow model stays on the CPU). The Run on control in each downloaded model's details offers Auto, CPU, GPU and NPU, listing only devices that model supports on this machine. Auto picks the best available device and falls back when one fails to prepare. Each model's row shows a listening score and the speed bars of the device it runs on, a Recommended tag, and, in its details, a progress line while a device prepares. The ratings ship with the app and were measured on one machine (see Platform support).
- Speed from 0.5x to 2.0x and pitch from -6 to +6 semitones, applied by time stretching with a single pass over the audio. A speed or pitch change applies from the next sentence. Pause lengths after punctuation scale with the speed.
- Reading is streamed. Several sentences are synthesized in parallel (up to three, fewer when memory is short) while playback streams ahead with a bounded read-ahead. When a model or device synthesizes slower than playback, reading pauses and the popup shows Buffering until enough audio is ready. Silence at the edges of each sentence is trimmed and replaced with a pause that suits the punctuation. Supertonic on the GPU uses six fixed input sizes that are warmed up when the model loads, and on the NPU every model uses fixed input shapes.
- Text is prepared as Markdown, so formatting marks are not spoken, and fenced code blocks are replaced by the words "code block skipped" unless Read code blocks is switched on. Text with very long unbroken runs is still read to the end.
- Technical reading is on by default and speaks paths, file names, extensions, flags, versions and code names the way an engineer would say them. Slashes, underscores, dots and dashes are named, so `tests/lib.sh` is read as "tests slash lib dot S H" and `--dry-run` as "dash dash dry dash run". A leading `~` is read as "home". Names in camelCase or snake_case are split into words. A known extension is read as its letters or name (".md" as "markdown", ".yaml" as "Y A M L"), a `:line` or `:line:column` suffix is read as "at line 684 column 7", each dot of a version is spoken (`v0.10.0` as "version 0 dot 10 dot 0"), and the `src` folder is read as "source". An acronym from the vocabulary is spelled in any letter case when it is a whole word or a whole part of a hyphenated word, so "the cli tool" is read as "the C L I tool" and `cli-tool` as "C L I tool", while words that only contain one, such as "click", "client", "clis" and "decline", are left alone. Ordinary prose, decimals and numbers are left as they are, and so are abbreviations such as "e.g.". Web links are read as "link to <site>".
- Three toggles in Read aloud, Settings control it: Technical reading (on by default), Read full paths (on by default; off reads only the file name of a path) and Read full links (off by default; on reads the site and its path instead of only the site). Read full paths and Read full links apply only while Technical reading is on. Changing any of them while reading applies from the current position without repeating text that was already spoken.
- Pronunciations come from a built-in vocabulary that you can extend. The file `tts-vocabulary.json` in the app data directory is created on first use with no entries and is read again at the start of every read, so an edit applies to the next read without a restart. It can add or override symbols, extensions, terms, acronyms and checked examples. A term can match a whole word, any part of one, a prefix, a suffix or a regular expression. An optional `models` section holds entries for one voice model id that apply only while that model is selected. Every entry of yours wins over every built-in entry, whatever either one's match type: a read uses your entries for one model, then your entries for all voices, then the built-in entries for that model, then the built-in entries for all voices. An optional `disabled` object, at the top level for all voices or inside a `models` section for that model, switches entries off without deleting them: `"disabled": {"mine": {...}, "builtin": {...}}`, each holding lists of `symbols`, `extensions`, `terms` and `acronyms` keys. `mine` switches off your own entry, so the built-in one applies again, and `builtin` switches off a built-in entry, acronyms included, so that text is left to the voice. A top-level `builtin` switch turns that built-in entry off for every voice, including in the built-in `models` sections, so it keeps working when an update moves the entry into a voice's section; one inside a `models` section acts on that section only. An optional `"acronym_style": "capitals"`, at the top level or inside a `models` section, gives that voice acronyms as written capitals ("CLI") instead of spaced letters ("C L I", the default, or `"spaced"`); the same layer order picks the style. A term written as `{"skip": true}` (or the empty string `""`) is not spoken at all. The word before it ends in one punctuation mark: the strongest of its own and those after the skipped terms (`?` and `!`, then `.`, `;`, `:` and `,`), so "Ticket ABC-123, ABC-123. Next one" with `ABC-123` skipped reads "Ticket. Next one." and the sentence ends and pauses as if the mark were written there; the highlight of that word covers the skipped terms. That punctuation never moves back across the pause after a heading, paragraph, list item or code block; a skipped term right after such a pause drops its punctuation, and nothing empty or only punctuation is sent to the voice. Spoken replacements may hold only letters, digits and spaces, including Devanagari and Gurmukhi vowel signs, virama and nukta.
- A vocabulary file that cannot be used never fails or delays a read. Reading falls back to the built-in vocabulary, and a "Vocabulary File Has an Error" warning (notice code `VocabularyInvalid`) names the file and the error, with line and column when known. A file that is not valid JSON or has an unsupported version, an entry that is not valid, text that is not UTF-8, a file over 1 MiB and anything that is not a regular file are all handled this way. The warning is shown once for each distinct error and is cleared by the next successful load.
- `vaakora-tts --check-vocabulary [file]` runs every example in the built-in vocabulary, or in the built-in vocabulary merged with your file. It prints PASS or FAIL for each example and exits with a failure status if any example fails, so a vocabulary edit can be checked before it is used. An example without a `model` runs against the shared vocabulary and every model that has entries. A model's own `symbols` may change the reading, but any other model entry that changes the reading of a shared example fails it.
- Saving vocabulary changes from the app rewrites `tts-vocabulary.json` in a standard layout (two-space JSON, symbol, extension and switch keys sorted) and keeps every other entry, with terms and acronyms in their file order. The new text goes to a temporary file beside the real one, which then replaces it in one step, through to the target when the file is a symbolic link and with its permissions kept. A save is refused, leaving the file as it was, when the file changed on disk since it was loaded, when it has an error, or when the result would be larger than 1 MiB.
- Read aloud has a Vocabulary tab. It lists every reading, built-in and yours, as a two-line row at every window width (no table, no horizontal scroll): a switch, what is written, an arrow, what is said, whether it is Yours or Built-in, Listen and Edit; below that the struck-through built-in default, the kind and how it matches, with the models it applies to as read-only chips; and, when it never applies, a line in the warning colour. There is one row for each distinct reading: rows with the same written text, kind, spoken words, match options and switch collapse into one, so an acronym that three models spell the same shows once with three model chips, and a separate row appears only when a model really says it differently (for example `/` is read as "slash" by most models and differently by the Hindi and Punjabi models, so it has three rows, the shared one marked "except" those two). An "All models" chip means the row applies to every model; the chips on a row are read-only. Applies to in the entry dialog is a list of checkboxes, All models first, then each downloaded voice model and any model the entry already names that is not downloaded, which stays checked; several can be checked. Checking a model for your own entry saves the same entry in that model's section and unchecking one deletes it there; for a built-in entry whose reading you keep, unchecking a model switches it off for that model and checking it again switches it back on. Every save is one save planned from the table as it is when the save runs: a model that another entry of yours for the same text already holds, or a built-in change no switch can make, turns Save off with the reason, and an entry is never saved with no model. When your entry overrides a built-in one at the same scope, they show as one row: your words marked Yours, the built-in words struck through below as "default:" (with the models it belongs to when only some of the row's models override a built-in entry), and Reset to default in the entry dialog, which brings the built-in entry back for the models that override one. Each row has a switch (which switches every model the row lists, in one save; switching off a built-in row for all models saves the other readings of that entry that the row does not list, such as the Hindi and Punjabi slash, as your own entries first, because a built-in all-models switch would otherwise turn those off too), Listen and Edit, where Listen plays the entry's sample with the voice model the entry belongs to or the selected one. Add entry and Edit open the entry dialog, which takes the written text, what to say or Skip, the kind, the match (whole word or anywhere in a word, and case) and Applies to, and holds Delete and Reset to default. Delete removes your own entry after asking inline in the dialog footer; built-in entries cannot be deleted, only switched off, so their Delete is shown off with that reason, and changing a built-in entry's reading saves your own version on top of it. Above the list, a toolbar that stays in view while the list scrolls has a search box for the written and spoken words, Correct a reading and Add entry, and below them the Model, Kind and Source (Built-in, Yours, or Changed by you, meaning built-in entries you overrode, switched off or shadowed) filters and a Problems chip that narrows the list to rows with a problem. A search or filter that matches nothing says what matched nothing and offers Clear filters. The Acronym style per model section follows the list. Under a row the tab says when it never applies: always beaten by a higher-priority entry, unable to match and why, or switched off. When the file changed on disk, the table reloads: a switch or acronym style change asks you to make it again, and an open entry dialog keeps what you typed, says the file was reloaded and saves against the reloaded file when you press Save again; when the file has an error, the tab shows its path and the reason, says built-in readings are used until it is fixed, offers Reload and Open folder, and turns editing and the switches off while Listen and the filters keep working.
- The Vocabulary tab has a Correct a reading button for fixing how a text is read. It opens the Correct a reading dialog, the same dialog as Add entry and Edit: type or paste the written text and press Next, and Vaakora shows how it is spoken. Edit the words it should say, press Listen (in the dialog footer) to hear them with the selected model, and see what the edit saves as and who it reaches (for example `.md` read as "dot M D" for every .md file, with a switch to save only the exact text). Choose All models or one downloaded voice model every time, then Save. An edit that no single rule explains, that changes more than one written word or that the output rules reject shows its reason and cannot be saved. Closing the dialog after a change asks "Discard your changes?" first, and when the vocabulary file changed on disk the dialog keeps what you typed, says the file was reloaded and saves against the reloaded file when you press Save again. Add entry and Edit choose their models with the Applies to list in the entry dialog. Each downloaded model has an acronym style, spaced letters (C L I) or written capitals (CLI), set in the collapsed Acronym style per model section at the bottom of the Vocabulary tab. A correction for one model is checked against that model, and an emptied word can be saved as a skip.
- A correction, or an entry in the entry dialog, can be checked across models before saving. For All models, Play all plays the text on each downloaded voice model in turn (for a correction, the selected text as each model will read it once the rule is saved; for an entry, its spoken words) at the current speed with that model's chosen or default voice, naming the model as it plays; for one model, Listen plays that model. Alongside, each model says the words and the current speech-to-text model transcribes them, and the dialog shows "heard right" or "missed: <what was heard>" per model (lowercase, punctuation ignored, spaced letters joined, so "G P U" matches "GPU"). The check is advisory and never blocks saving: when a model misses a rule for all models, you can save for all models anyway, save only for the models that passed (one rule per model) or pick one model. Changing a match option checks again. An acronym is played and checked the way each model reads acronyms (written capitals or spaced letters, as set in the Vocabulary tab). Models are loaded one at a time for the check, and the speech-to-text model is unloaded afterwards under the unload-immediately setting, unless a dictation or a newer check took it over. The transcription is raw: no custom-word correction, filler removal or post-processing, nothing is pasted and nothing is added to the speech-to-text history. A check is refused while a dictation records or a file transcribes, and a dictation that starts stops a running check and Play all. A model that is missing or fails reports only its own row.
- The Correct a reading dialog has a microphone button next to Should say. Press it, say how the text should be read, and press it again: the current speech-to-text model transcribes what you said and puts the words in Should say, where you can still edit them. Typing stays the main way to correct a reading. The transcription is raw: no custom-word correction, filler removal or post-processing, nothing is pasted, nothing is added to the speech-to-text history, and no recording overlay or sound is used. The recording goes only to speech-to-text and is never saved or sent anywhere. The microphone is refused while a dictation, a recording or a file transcription runs and while Read aloud is open, and a playing preview stops when it starts. A dictation started while the microphone records or transcribes always wins: the microphone stops and Should say is left as it was. The speech-to-text model is unloaded afterwards under the unload-immediately setting, unless a dictation stopped the microphone.
- Read aloud keeps a history of your reads on this computer, text only and never audio, in its own file `tts-history.db` in the app data directory. Each read is saved once its audio starts playing, and a read that never plays is not saved: the written text, the text actually sent to the voice, which written word became which spoken words, the time, the voice model, the voice and the speed. Reads with Technical reading off are saved too. Playing the same text again is not saved again unless the voice model or voice changed or a setting changed what is said. Two settings, separate from speech-to-text history, control it: how many reads to keep (5 by default, up to 1000) and when to delete them (keep nothing, keep only that many, or also delete reads older than 3 days, 2 weeks or 3 months). Keep nothing, or a limit of 0, saves nothing and empties the history. The rules apply when the app starts, at every save and when either setting changes. A setting change applies to saves still in progress, and Clear history also drops a read that was about to be saved. Clearing the history never touches the vocabulary, and a vocabulary change never alters saved reads. The history is opened, prepared and saved in the background, so it never delays reading or app start, and if it cannot be saved, reading goes on and the failure is logged.
- Read aloud, History lists your past reads, newest first, one per line: the date, the start of the text, the voice model and voice, and a Copy button. One read opens at a time, in place, and shows each written word with the words that were said for it directly under it, word under word, at the full width of the page, with changed words tinted and underlined (so they show without colour) and skipped words marked; the spoken words are exactly what was saved, nothing is prepared again. Copy text under the reading copies the text that was read. Drag over words to select a chunk, which snaps to whole words, and the Correct a reading dialog opens with that chunk as Selected, the saved spoken words as Spoken as and the read's voice model as the voice the rule is worked out against, so a rule saves and checks across voices like any other correction (Listen plays in the current voice until you choose where the rule applies). The tab has a toolbar that stays in view: a line saying how history is kept with a Change link to Read aloud, Settings, History, then Clear history, which asks inline with the number of reads it deletes and never touches the vocabulary. The history settings are in Read aloud, Settings, History: Keep history (Do not keep, Keep the latest N, or Keep the latest N with none older than 3 days, 2 weeks or 3 months) and Keep the latest (0 to 1000, applied when you leave the field or press Enter). Changing either reloads the stored reads, so reads it removed are gone at once.
- Dictation and reading never overlap. Starting a dictation stops reading and closes the popup. Pressing Read aloud during a dictation ends the recording, lets the dictation finish, then opens the popup.
- The voice engine runs as a separate worker process that is started when needed and unloaded after the existing model unload timeout. It refuses to start with less than 1 GiB of available memory. After three failed starts in a row it stays in a Failed state until a model is selected again.
- Model ids, voice lists and the allowed speed are read from the model catalog instead of lists repeated in each component, and a model with no saved voice reads with its own default voice. A voice list in the catalog replaces voice discovery from the pinned files.
- The ratings measurement commands take `--only <model id>[,<model id>]` to measure chosen models, `--max-load <n>` to refuse to start when the one-minute load average is above `n`, and `--merge <ratings.json>` to replace only the measured models in an existing ratings file and record the measurement date and highest load per model. Devices a model does not offer are recorded as unsupported without starting the worker.
- `vaakora-tts --synthesize-lines <model> <root> <device> <cache> <lines.json> <out-dir> --speed <s> [--voice <style>]` loads one voice model and writes one WAV per line of an audit file. The `tts_vocabulary_audit` developer example uses it to audit the built-in vocabulary one voice model at a time (any catalog model id): `corpus` writes a short carrier sentence for every built-in entry (an acronym both in capitals and in a hyphenated word), once read with the entry's rule and once with that entry switched off, as the voice would get it without the entry, three runs each; `score` transcribes them with a local speech-to-text model and decides each entry by majority, matching the way the voice check does (lowercase, punctuation ignored, spaced letters joined) against the written text, its letters spelled out or the rule's words (a spoken "dot" the recogniser writes as a dot joined to the next word counts), so an entry is needed, redundant (the raw text already comes through) or a defect (the rule itself does not); entries said only in a script the recogniser cannot write, and entries on a voice that spells both sentences out letter by letter, are marked not audited and stay with that voice. `combine` reads the stored results of several models and proposes a vocabulary file that removes redundant entries, keeps entries every model needs for all voices and moves the others into those models' `models` sections, with a decision table, the examples the proposal would fail and any audited sentence it would read differently. It never changes the built-in vocabulary.

In-app local post-processing

- New "Local (in-app)" post-processing provider that runs a small language model on the CPU through a bundled llama.cpp `llama-server`. No external service has to be installed or started, and transcripts never leave the machine.
- This build starts `llama-server` as a managed child process. It listens on a private Unix socket inside a directory that only the current user can open (mode 0700) under `XDG_RUNTIME_DIR`, or under the app data directory when that is not set, and it opens no network port. A random API key is generated for each launch and passed through the environment instead of the command line. The app stops the server on exit, and on Linux the kernel terminates it if the app dies without cleaning up.
- The model loads only when needed: it starts in the background when a post-processing recording begins, so recording is never delayed, and it unloads after the existing model unload timeout (a duration, Immediately, or Never).
- Before a model is loaded, its file is checked against its pinned size and SHA-256. A corrupt file is reported with advice to delete and re-download it, and a check that runs past the start deadline falls back to the raw transcript.
- Local post-processing never blocks a dictation on failure. A start deadline of 10 seconds applies, a server that exits unexpectedly is started again on the next dictation, and after three failed starts in a row the model enters an error state. When the last of them was a start timeout, for example under heavy machine load, the first dictation after 5 minutes tries one more start and recovers on its own; after any other failure the error state lasts till a model is selected or deleted, or the app restarts. Every failure falls back to the raw transcript.
- Five downloadable local models, each pinned to a Hugging Face revision with a fixed size and SHA-256: S1-mini by Superwhisper, Quill 0.8B, Quill 2B, Qwen3-4B-Instruct-2507 and Muesli 2B (all Q4_K_M quantizations). Each model shows its attribution and a link to its model card.
- Models are downloaded and deleted on demand through the verified, resumable downloader. Download progress and errors survive leaving the page, and a stale error is cleared before the next model action.
- S1-mini is driven by Styling (casual, semi-casual, semi-formal, formal), Structure (prose, lists) and Context (general, email) dropdowns.
- Quill, Qwen3 and Muesli models use the selected prompt as their system prompt, and the Prompts group is shown for them. S1-mini uses its own fixed prompt, so the prompt editor is hidden for it with a note. If the selected prompt is missing or empty, post-processing is skipped and the raw transcript is kept.
- Long transcripts are split at sentence boundaries, processed in order and rejoined. The token budget for each chunk and for the reply is estimated per script, so Gurmukhi, Devanagari and other Indic text gets a larger reply budget. A model that still reaches the limit falls back to the raw transcript. Output that loses more than half of the input words is rejected, and think blocks and invisible characters are stripped from model output.
- A live status label (Not loaded, Loading, Ready, Error with the reason) is shown next to the model controls.
- The RPM bundles a static, CPU-only `llama-server` at `/usr/lib/Vaakora/llm/llama-server`. The `HANDY_LLAMA_SERVER` environment variable overrides the path for development.
- An opt-in integration test (`HANDY_LOCAL_LLM_IT=1`) runs the real `llama-server` against golden outputs.

### Platform support

- Built and tested on Fedora 44 (KDE Plasma, Wayland) on an Intel Core Ultra 7 258V, and packaged as an RPM only.
- Local post-processing needs Unix sockets and uses the Linux parent-death signal to stop `llama-server` if the app dies. The `llama-server` bundling is Linux-only.
- Read aloud's worker process, its OpenVINO libraries, the parent-death signal and the 1 GiB free-memory check are Linux-only. On other platforms the memory check is skipped. Clipboard capture uses `wl-paste` or `xclip` on Linux.
- The device ratings shown in Models, Read aloud were measured on that one machine. Other hardware may rank devices differently.
- Windows and macOS are not supported by these features yet.
